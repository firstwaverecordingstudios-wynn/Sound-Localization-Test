# MASTER_WORKFLOW

This document defines the standard collaborative workflow between the user and Claude for all MATLAB projects. Claude should read this file at the start of every project session before any work begins.

---

## Overview

Every project follows **4 sequential phases**. Claude must request explicit user permission before entering each new phase. No phase may be skipped.

1. Defining
2. Planning
3. Implementation
4. Tutorial

---

## Phase 1 — Defining

**Purpose:** Establish a thorough, shared understanding of the project before any planning or coding begins.

**Process:**
- The user describes the project's requirements and objectives.
- Claude takes detailed notes and asks clarifying questions until it has a complete understanding of:
  - The acoustic/physical phenomena being modeled or measured
  - Whether the solution is numerical, analytical, or both
  - Any measurement, playback, or experimental components
  - Expected inputs, outputs, and results
  - The intended audience and their technical level
- Claude does not proceed until it is confident it fully understands the project.

**Exit condition:** Claude summarizes its understanding and asks: *"I believe I have a thorough understanding of the project. May I proceed to the Planning phase?"*

---

## Phase 2 — Planning

**Purpose:** Collaboratively define the final scope and produce a written plan before any code is written.

**Process:**
- Claude presents potential approaches, tradeoffs, drawbacks, and suggested upgrades or enhancements it considers valuable.
- User and Claude discuss and decide together on the final implementation strategy.
- Claude produces two deliverables saved to the project's `documents/` folder:
  1. **PRD.md** — Product Requirement Document outlining goals, scope, physics/acoustics context, and final design decisions.
  2. **TASKS.md** — A numbered, ordered checklist of every implementation task Claude must complete.
- **The user must review and approve both documents before any code is written.** Claude waits for explicit approval and incorporates any requested edits.

**Exit condition:** User approves the PRD and TASKS. Claude asks: *"The planning documents are approved. May I proceed to the Implementation phase?"*

---

## Phase 3 — Implementation

**Purpose:** Write, test, and refine the working MATLAB code.

**Process:**
- Claude implements the code according to the approved PRD and TASKS.
- Code standards (non-negotiable):
  - **Highly readable:** Clear variable names, logical structure, generous use of section headers and inline comments.
  - **Physics/acoustics-forward:** Comments must explain the underlying physical and acoustic meaning of equations and parameters, not just what the code is doing syntactically.
  - **Efficient:** Avoid redundancy; use vectorized operations where appropriate.
  - **Accessible:** Someone with minimal software development experience should be able to follow the code with ease.
- Claude and user go back and forth testing the software iteratively.
- Claude maintains a **LOG.md** file in the project's `documents/` folder, logging every change or test with:
  - Date and time
  - Description of the change or test
  - Rationale

**Exit condition:** The project meets all standards set in the PRD. Claude asks: *"The implementation meets our defined standards. May I proceed to the Tutorial phase?"*

---

## Phase 4 — Tutorial

**Purpose:** Ensure the user has a deep understanding of the final code before the project is closed.

**Process:**
- Claude walks through the final code section by section, explaining:
  - What the code is doing
  - Why it is structured that way
  - The underlying physics and acoustics at each step
- After each section, the user may:
  - Ask questions or request clarification
  - Elect to return to the Implementation phase to make edits
- Once the user is satisfied, Claude generates a **TUTORIAL.md** file saved to the project's `documents/` folder capturing the full explanation.

**Exit condition:** User approves the tutorial. Project is complete.

---

## Project Folder Structure

Every project is organized as follows:

```
PROJECT_NAME/
├── PROJECT_NAME.m          ← Main MATLAB script
├── documents/
│   ├── PRD.md              ← Product Requirement Document
│   ├── TASKS.md            ← Implementation task checklist
│   ├── LOG.md              ← Change and test log
│   └── TUTORIAL.md         ← Generated after Tutorial phase
├── archive/                ← Deprecated versions of the .m file
└── results/                ← Figures and output files generated by the script
```

---

## General Rules

- Claude never enters a new phase without explicit user permission.
- Claude never writes code before the PRD and TASKS are approved.
- The LOG.md is updated every time a change or test occurs — no exceptions.
- All code prioritizes readability and physical intuition over cleverness.
- Projects may involve: acoustic modeling (numerical and/or analytical), acoustic measurements, audio playback for experiments, signal processing, and visualization.
